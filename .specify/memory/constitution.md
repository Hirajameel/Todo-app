# Hackathon II: The Evolution of Todo Constitution

## Core Principles

### I. Spec-Driven Development Only
No manual coding is allowed. All implementation must be generated by Claude Code based on validated specifications. Every line of code must trace back to a spec file and task.

### II. Claude Code + Spec-Kit Plus as Single Source of Truth
All agents (Claude Code, future sub-agents) must follow the Spec-Kit lifecycle: Specify → Plan → Tasks → Implement. No freestyle coding, no improvisation.

### III. Monorepo Architecture
Entire project (console, full-stack, chatbot, k8s, cloud-native) lives in one GitHub repository for maximum context sharing with Claude Code.

### IV. Clean, Maintainable, Production-Ready Code
Follow PEP 8 (Python), ESLint + Prettier (Next.js), clear naming, type hints, docstrings, modular structure.

### V. Stateless Where Possible
Especially in Phase III–V: backend, MCP tools, and chat endpoints must be stateless — all state in Neon DB.

### VI. Security First
JWT-based authentication (Better Auth), user isolation (each user sees only their tasks), no hard-coded secrets.

### VII. AI-Native Thinking
Prefer agentic patterns, reusable intelligence (sub-agents, MCP tools), and event-driven architecture (Kafka/Dapr in Phase V).

### VIII. Documentation & Traceability
Every feature, API, model, and deployment step must have a corresponding spec file. Specs history folder must preserve all iterations.

## Key Standards

### Language & Tools (non-negotiable):
- Phase I: Python 3.13+, UV, in-memory
- Phase II: Next.js 16+ (App Router), FastAPI, SQLModel, Neon PostgreSQL, Better Auth (JWT)
- Phase III: OpenAI ChatKit, OpenAI Agents SDK, Official MCP SDK
- Phase IV: Docker, Minikube, Helm, kubectl-ai, kagent
- Phase V: Dapr (full: Pub/Sub, State, Jobs, Secrets), Kafka/Redpanda, DigitalOcean Kubernetes (DOKS)

### Code Quality:
- Type hints everywhere (Python: typing, Next.js: TypeScript)
- Docstrings on all public functions/classes
- Error handling with HTTPException (FastAPI) and clear user messages
- Logging (basic in Phase I–III, structured in Phase V)

### Testing Mindset (even if not full tests):
- Every generated code must be manually verified
- Edge cases documented in acceptance criteria

### Spec Format:
- Markdown only
- Clear sections: User Stories, Acceptance Criteria, Examples
- Reference other specs with @specs/...

### Commit Messages:
- Conventional commits: feat:, fix:, chore:, docs:, refactor:
- Include task ID if applicable: "feat: add task creation [T-001]"

## Constraints
- No manual code writing — only Claude Code generated (judges will check prompt history and spec iterations)
- No changing core tech stack without updating this constitution and getting explicit approval (in real team = from lead architect)
- All API endpoints must be protected by JWT (Phase II onwards)
- Database: only Neon PostgreSQL (serverless)
- Deployment target for final phase: DigitalOcean Kubernetes (DOKS)
- Demo video: maximum 90 seconds (first 90s only watched)

## Success Criteria
- All 5 basic features implemented in every phase (Add, Delete, Update, View, Mark Complete)
- Clear spec → plan → tasks → code traceability visible in repo
- No manual code commits (only Claude-generated with prompt evidence)
- Working demo at each phase (console → web → chatbot → Minikube → DOKS)
- Stateless architecture in Phase III–V (conversation state in DB)
- Bonus features attempted: reusable intelligence, Urdu support, voice commands
- README contains:
  - Setup instructions (local + cloud)
  - Architecture diagram (text or image)
  - Spec-driven workflow explanation
  - Links to deployed app + video

## Governance
This constitution is the highest authority in case of conflict with any spec, plan, or task. Any deviation from this constitution must be documented in a new spec file, update this constitution.md, and be committed with justification. All amendments must preserve the core principles of spec-driven development and Claude Code as the primary implementation mechanism.
